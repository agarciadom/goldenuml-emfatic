# goldenuml-emfatic

This research artifact extends the Golden UML ModelSet with Ecore metamodels and their [Emfatic](https://eclipse.dev/emfatic/) equivalents, and studies how well LLMs (directly called, or as part of a code-based agent) can derive Ecore metamodels from PlantUML class diagrams and natural-language domain descriptions.

The Golden UML ModelSet is available from Zenodo:

* C. Verbruggen et al., “Golden UML Modelset”. Zenodo, Aug. 28, 2025. doi: [10.5281/zenodo.16985873](https://doi.org/10.5281/zenodo.16985873).

## Repository structure

* [`modelset`](./modelset): Local copy of the ModelSet, extended with Ecore metamodels derived from the PlantUML descriptions and natural-language domain descriptions using various LLMs. See [more details below](#contents-of-a-modelset-case).
* [`puml2emfatic`](./puml2emfatic/): Java (Gradle) application that [drives the LLM-based conversions](#building-and-running-puml2emfatic) (PlantUML/natural language to Ecore) and the deterministic Ecore-to-Emfatic conversion, plus commands to compare generated models against the reference ones.
* [`nl2flexmi-agent`](./nl2flexmi-agent/): Python experiment (using `smolagents`) that [builds up an Ecore metamodel incrementally](#nl2flexmi-agent) from a natural-language description via a tool-using agent, producing a Flexmi model. Its tools, prompts, and Pydantic types are autogenerated (see `agent-generator`) from an Emfatic metamodel describing the subset of Ecore the agent can build.
* [`agent-generator`](./agent-generator/): Java (Gradle) application using [Epsilon](https://eclipse.dev/epsilon/) EGL/EGX to [generate the Python tools, prompts, and Pydantic model classes](#regenerating-the-agents-tools) used by `nl2flexmi-agent`, from an Emfatic metamodel.
* [`data-analysis`](./data-analysis/): Python (uv) scripts that [collate the results](#data-analysis) scattered across `modelset` into CSVs and produce the violin-plot figures and LaTeX summary tables used to compare models/approaches.

### Contents of a ModelSet case

Each case directory under `modelset` (e.g. `modelset/AirTravel`) contains:

* `description.md`, `plantuml.txt`/`.png`/`.svg`, `metadata.txt`: the original ModelSet materials (natural-language description, PlantUML source and renders, and metadata), plus `extramaterial/` for any other source files (e.g. class diagrams in other tools).
* `converted.ecore` / `converted.emf`: the reference Ecore metamodel manually derived from the PlantUML diagram, and its Emfatic rendering.
* `nl2ecore/<model>/`: per-LLM results of generating Ecore directly from `description.md` (`generated.ecore`/`.emf`, `compare-models.csv`, `compare-names.csv`, and captured stdout/stderr logs).
* `nl2flexmi/<model>/`: per-LLM results of the `nl2flexmi-agent` tool-using approach (`generated.flexmi`/`.emf`, `generated.csv` with token/timing stats, comparison CSVs, and logs).
* `a2a-stream/`: results of generating Emfatic from `description.md` via the MOSAICO A2A agent (`metamodel.emf` and logs).
* `raw-llm-stdout.txt`: logs from the original PlantUML-to-Ecore conversion.

## Building and running puml2emfatic

First, build the all-in-one JAR:

```shell
cd puml2emfatic
./gradlew build
```

You can then list available subcommands for the tool with:

```shell
java -jar build/libs/puml2emfatic-*-all.jar
```

To see specific help on a subcommand, use `--help`.
For example, for the `ecore2emfatic` subcommand:

```shell
java -jar build/libs/puml2emfatic-*-all.jar ecore2emfatic --help
```

Available subcommands include:

* `puml2ecore`: LLM-driven conversion from a PlantUML class diagram to Ecore (XMI).
* `nl2ecore`: LLM-driven conversion from a natural-language domain description to Ecore (XMI).
* `ecore2emfatic`: deterministic conversion from an Ecore/Flexmi model to Emfatic.
* `a2a-stream`: LLM-driven conversion from a natural-language domain description to Emfatic, communicating via the MOSAICO AISP to the MOSAICO [reference agent](https://gitlab.eclipse.org/eclipse-research-labs/mosaico-project/mosaico-reference-agent).
* `compareModels`: EMF Compare-based structural comparison between two Ecore models.
* `compareNames`: Jaccard-similarity comparison of the names used in two Ecore models.

Note that if you use a command that is based on an LLM, you will need to copy and customise the `.env.template` file:

```shell
cd puml2emfatic
cp .env.template .env
# customise .env as appropriate
```

### Batch scripts

The following convenience scripts under `puml2emfatic` rerun a conversion or comparison across every case in `modelset` (each skips cases whose output already exists, so it is safe to delete only the outputs you want to regenerate before rerunning):

```shell
cd puml2emfatic
./convert-puml2ecore-all.sh    # PlantUML -> converted.ecore (raw-llm-std{out,err}.txt)
./convert-nl2ecore-all.sh      # description.md -> nl2ecore/$MODEL_NAME/generated.ecore
./convert-a2astream-all.sh     # description.md -> a2a-stream/metamodel.emf (via MOSAICO agent)
./convert-ecore2emfatic-all.sh # converted.ecore / generated.ecore / generated.flexmi -> Emfatic
./compare-models.sh            # generated.emf vs converted.ecore -> compare-models.csv / compare-names.csv
```

If an Ecore-to-Emfatic conversion fails because the source file is not well-formed, this is logged to the console and an `emfatic-stderr.txt` file is created next to the source with the error message; a successful conversion deletes any leftover `emfatic-stderr.txt` from a previous run.

## nl2flexmi-agent

`nl2flexmi-agent` is a Python (uv) project that experiments with an LLM agent building up an Ecore metamodel step by step from a natural-language description, via autogenerated tools backed by a Pydantic layer.

```shell
cd nl2flexmi-agent
cp .env.template .env
# customise .env with appropriate values (e.g. MODEL_NAME, API_BASE, API_KEY)
uv sync
uv run main.py samples/library.txt samples/library.flexmi
uv run -m pytest   # run tests
```

To rerun this conversion across every case in `modelset`:

```shell
cd nl2flexmi-agent
./convert-nl2flexmi-all.sh
```

### Regenerating the agent's tools

The tools, prompts, and Pydantic model classes consumed by `nl2flexmi-agent` are generated by `agent-generator`.

To run this transformation from the console, run:

```shell
cd agent-generator
./gradlew build
java -jar build/libs/agent-generator-*.jar src/test/resources/model.xmi ../nl2flexmi-agent
```

## data-analysis

`data-analysis` is a Python (uv) project that aggregates the per-case, per-model results scattered across `modelset` into CSVs, then produces comparison figures and summary tables:

```shell
cd data-analysis
./00-run-all.sh
```

This runs, in order:

1. `01-nl2ecore.py` / `02-nl2flexmi.py`: collate token counts and comparison metrics from `modelset` into `nl2ecore.csv` and `nl2flexmi.csv`.
2. `03-violin-jaccard.py`, `04-violin-input_tokens.py`, `05-violin-output_tokens.py`: produce violin-plot figures (PNG/PDF) comparing Jaccard similarity and token usage across models and approaches.
3. `06-summary-table.py`: produce LaTeX booktabs summary tables (`nl2ecore-summary.tex`, `nl2flexmi-summary.tex`) from each results CSV.
4. `07-mannwhitney-jaccard.py`: conduct Mann-Whitney U tests to perform statistical significance tests across the Jaccard scores of the selected frontier model (using direct prompting) and the selected local LLMs.
